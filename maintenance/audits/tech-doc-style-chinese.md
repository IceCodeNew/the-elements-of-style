- **Older copy not used:** ninehills/skills holds an older copy of this skill (`tech-doc-style-chinese` @ `f3e82a7`, 2026-06-22), the copy that `deslop-zh` credits. It is not used; this audit follows the original repository. The `DZ` rows in [`deslop.md`](deslop.md) restate several of the same rules; the notes below cite them where they agree or differ.
- **Use:** the whole skill, loaded on top of the final skills, did not improve the Chinese technical cases (see `evals/results/README.md`). Each principle that no final rule covered became a candidate rule and was tested on its own in the add-back step. `coverage.md` gives each outcome.
- **IDs:** `TD-S` SKILL.md, `TD-T` terminology-and-typography.md, `TD-A` api-status-copy.md, `TD-C` controlled-technical-chinese.md, `TD-P` project-overrides-example.md. The files come in the order of SKILL.md §参考资料路由, and the rows of each file in source order.

Rubric: `.agents/skills/updating-upstream-rules/rubric.md`. The last column names the rule. For `X-DUP`, it is the final rule that says the same, or a candidate of the 2026-10 update marked "(dropped)". For any other destination, it is the candidate rule that merges the row.

Conventions used in this audit:

- Granularity. One row per rule. Checklist items (§最终检查, 数字排版还应检查) and process steps (§编辑流程) get one row each. The jargon catalogue gets one row, and each vocabulary table (replacement pairs, capitalization, misspellings, context words, quantities, status words) one row per entry. The twelve 回归样例 are worked examples and get one row each, as in `deslop.md`; their notes record where an "after" breaks a rule. The bad/good tables and inline examples illustrate a row. The test cases use them, and each case names its rows in `source`.
- `X-DUP` names a final rule if one says the same. If only a dropped candidate says it, the row stays `X-DUP` of that candidate. A row that adds a condition or a case that the candidate lacked carries a kept destination (TD-S24, TD-S25, TD-T29).
- SKILL.md and a reference file can state one new principle in several rows. All of them carry the kept destination, and one candidate rule merges them.
- `both.keep-certainty`, `both.one-topic-per-paragraph`, `both.name-every-cause` and `both.state-dont-stage` are final rules of `writing-personal` only; the ablation dropped them from `writing-tech`. A row that duplicates one of them says so.
- UI, error and button text are in the rubric's TECH list, so TD-S41 to TD-S43 are `TECH`. Product introduction pages, solution pages, landing pages, their call-to-action buttons and brand voice are not. Rows TD-S02, TD-S21, TD-S35, TD-S36 and TD-C04 keep no rule for those parts.
